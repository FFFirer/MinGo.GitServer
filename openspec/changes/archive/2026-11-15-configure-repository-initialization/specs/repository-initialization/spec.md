## ADDED Requirements

### Requirement: 创建仓库时可选择初始化

创建表单 SHALL 提供默认未选中的「用 README 初始化」选项。创建 API SHALL 接受可选布尔字段 `initialize`，省略时按 `false` 处理。

#### Scenario: 立即用 README 初始化

- **WHEN** 用户勾选初始化并成功创建仓库
- **THEN** 指定的默认分支存在且包含一条带 `README.md` 的初始提交
- **AND** 网页文件和提交页以及普通 Git clone 可访问该提交

#### Scenario: 创建空仓库

- **WHEN** 用户不勾选初始化或 API 请求省略 `initialize`
- **THEN** 仓库可接收 Git 推送，且创建操作不生成提交或分支引用
- **AND** 文件首页显示克隆地址、首次推送指引和新建文件入口

### Requirement: 首次成功创建分支时确定默认分支

新建空仓库 SHALL 根据首次实际成功创建的分支确定默认分支。Git `HEAD` 和仓库元数据 SHALL 指向同一分支，并在后续推送中保留该选择。

#### Scenario: 首次只推送 master

- **GIVEN** 空仓库预设分支名为 `main`
- **WHEN** 用户首次成功推送 `master`
- **THEN** `master` 成为默认分支并保留推送的提交历史
- **AND** 重新打开仓库或执行普通 Git clone 时默认看到 `master` 的文件

#### Scenario: 首次推送成功创建多个分支

- **WHEN** 空仓库的一次推送成功创建多个分支
- **THEN** 若预设分支名在实际创建的分支中，选用该分支
- **AND** 否则选用按完整引用名序数排序的首个分支

#### Scenario: 推送没有成功创建分支

- **WHEN** 空仓库只收到标签，或推送未成功写入任何分支
- **THEN** 仓库继续等待首次分支创建
- **AND** 已成功写入的标签仍可在标签页查看

#### Scenario: 在网页中创建首个文件

- **WHEN** 用户在等待初始化的空仓库中成功提交首个文件
- **THEN** 该提交所在分支成为默认分支

#### Scenario: 并发首次推送

- **WHEN** 两次并发推送均为待初始化仓库创建分支
- **THEN** 默认分支由先完成分支创建的一次操作确定
- **AND** 稍后完成的推送不重新选定默认分支

#### Scenario: 同步默认分支时中断

- **WHEN** 首个分支已写入，但服务在同步默认分支和初始化状态时中断
- **THEN** 服务恢复后在提供仓库视图或处理新的引用写入前完成同步
- **AND** 已写入的提交仍可访问
