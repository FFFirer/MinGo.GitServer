# 仓库管理和网页提交

## 行为与契约

前置条件为 Git 可执行文件可用，SQLite 已初始化，管理员已登录。JSON 请求和响应参见同目录上一级的 OpenAPI 契约。Git 通过独立的 Smart HTTP 路由访问。

- FR-001 管理员可以列出、创建、查看和删除仓库。重复名称返回 409。删除后的仓库不再通过名称或 UUID 查到。
- FR-002 分支与轻量标签从完整提交 SHA 创建。引用名称可包含斜杠。默认分支禁止删除。
- FR-003 可按分支或标签读取历史，按完整 SHA 读取提交和第一父提交差异。目录返回快照 HEAD，文件可使用该 SHA 读取同一快照。
- FR-004 单次网页提交创建、编辑或删除一个文件。请求提供分支、相对路径、提交说明与预期 HEAD。只有空仓库的默认分支接受空预期 HEAD。失败的引用更新返回 409。
- FR-005 登录后可轮换 Git 令牌。移动端可在单列布局浏览仓库、文件和历史，并全屏编辑。
- NFR-001 文本预览及写入上限 1 MiB，Git 查询输出上限 2 MiB，历史每页最多 100 条。文件路径禁止穿越和访问 Git 元数据。二进制和无效 UTF-8 不在网页显示。
- NFR-002 管理接口由 Cookie 保护，修改请求要求防伪令牌。操作不触碰工作树，引用更新使用 Git 原子比较。

## 验收

- 给定空仓库，首个 Git push 或首个 Web 提交可创建默认分支。
- 给定当前 HEAD 为 A，两个编辑者从 A 提交，只有一个成功。以 A 为父提交的 Git push 和网页提交竞争时也只有一个成功。
- 给定目录或分支名称包含斜杠，编码后的 API 查询能找到该项。文件路径穿越被拒绝。
- 给定 375px 视口，可登录、创建仓库、创建并修改文件、查看差异、切换分支。320px 至桌面宽度无页面级横向溢出。
- 给定完整停机快照，恢复至新目录后可登录并克隆原仓库。

验证入口为 `node tests/protocol.mjs` 与 `npm run test:e2e`。Linux 容器、目标资源和真机输入另按部署验收记录。
