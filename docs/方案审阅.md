# 方案 v1 审阅

保留 .NET 10、Minimal API、SQLite、Git CLI、Smart HTTP、TypeScript/Vite、Web Components 和 CodeMirror。部署仍为单进程、单数据库和持久卷。按仓库与 Git 协议、引用和查询、网页提交、前端、部署验证的顺序落地。

- MVP 后端采用一个项目内的模块边界。单管理员模型用固定身份和稳定的仓库 UUID。多用户和 ACL 延后。浏览器写入使用防伪令牌，Git 使用可轮换的独立令牌。
- 由应用把 URL 中的仓库名称映射到 SQLite UUID，再为 CGI 构造路径。仅提供 Smart HTTP 服务，查询和协议共享 Git 并发上限。保留原始 Git 错误语义和传输的流式行为。
- 创建用空 bare 仓库，允许 Git 首次推送和 Web 首次提交。网页使用独立 index 写入对象，再用预期 SHA 比较并交换引用。引用名称和文件路径走查询参数或请求体。预览使用树结果返回的 commit SHA。
- 删除以数据库墓碑为准，通过同卷移动隔离仓库。启动时处理上次中断留下的目录。备份采用停机快照，包含 SQLite、Git 对象、隔离目录及数据保护密钥。
- 前端类型由运行时导出的 OpenAPI 3.1 生成。协议验收脚本启动真实应用并调用 Git CLI，浏览器流程由 Playwright 覆盖。实际硬件性能和真机键盘体验需在目标环境验收。

协议验收采用 Node.js 和系统 Git，覆盖应用、SQLite 与 Git 之间的集成。容器默认由 Kestrel 终止 TLS，也支持配置可信代理。隔离仓库由管理员在停机维护时清理。单用户可轮换一个 90 天 Git 令牌，同时拥有读写权限。
