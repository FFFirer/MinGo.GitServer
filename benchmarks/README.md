# 目标环境验收

使用 2 vCPU、2 GiB 的 Linux 主机和 Rootless Podman 部署 Release 构建。固定一份脱敏的停机快照，含 20 个仓库，每库 100–1000 个提交，总数据 1–2 GiB。每次测试恢复到新卷，记录主机、Git 版本、镜像摘要和快照校验值。

| 场景 | 测量 | 目标 |
| --- | --- | --- |
| 从容器启动到健康响应 | 5 次冷启动 | ≤5 秒 |
| 稳态空闲和普通浏览 | 记录应用 RSS 和 cgroup 内存 | RSS ≤100 / 150 MiB |
| 仓库列表、提交、目录和 1 MiB 文件 | 预热后每个端点 100 次，记录 P95 | 普通 API ≤200ms，20 仓库列表 ≤300ms |
| 大仓库 clone、fetch、push | 容器内存峰值、成功率、取消后进程树 | 常规负载 ≤768 MiB |
| 离线恢复 | 导入新卷、登录、clone、对比默认分支 SHA | 用户元数据和 Git 引用一致 |

容器指标可由 `podman stats` 和 cgroup v2 的 `memory.peak` 取得。先运行协议和浏览器验收，再用 Android Chrome 与 iOS Safari 检查虚拟键盘、粘贴和长文件滚动。记录数据集和每次测量结果后再判断部署验收是否完成。
